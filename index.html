1端口规则（Port Rules）

控制哪些入站端口对外开放或拒绝，最常用的一类规则。

字段含义
协议TCP / UDP（HTTP/SSH 选 TCP，DNS/SNMP 选 UDP）
端口单端口 8080，或范围 8000-8100
策略允许 = accept；拒绝 = drop（直接丢包不回应）
指定 IP留空 = 对所有来源生效；填了 = 只对该 IP 或网段生效（支持 CIDR）

典型场景：

  • 给 webssh 自己开放 3010：允许 + TCP + 3010 + 留空
  • 只让公司网段访问数据库：允许 + TCP + 3306 + 192.168.0.0/24
  • 屏蔽某端口对外暴露：拒绝 + TCP + 8080 + 留空
  • 只开 SSH 给运维一人：允许 + TCP + 22 + 192.168.0.88/32

底层命令：

  • 简单放行（无源 IP + accept）→ firewall-cmd --add-port=80/tcp
  • 带源 IP / 拒绝策略 → 走 rich-rule：
    --add-rich-rule='rule family="ipv4" source address="192.168.0.0/24" port port="3306" protocol="tcp" accept'
⚠ Docker 用 iptables 自己的链（DOCKER），firewalld 控制不了 docker run -p 暴露的端口，需在容器层处理。

2端口转发（Port Forwarding）

把进入本机的 A 端口流量转发到另一个端口（本机或远端）。等价于"端口映射 / 隧道"。

字段含义
协议TCP / UDP
源端口用户访问的端口（本机入口）
目标端口实际转发去的端口
目标 IP留空 = 本机；填了 = 转发到另一台机器（前提系统已开 IP forward）

典型场景：

  • 特权端口转到非 root 服务：80 → 8080，避免以 root 启动 Node
  • 本机当跳板：5020 → 192.168.0.50:5020，把内网设备暴露给外网某机
  • 协议隔离：对外 443 → 内部 8443
  • 上位机简化配置：上位机连 502，由 502 → 5020 转发到 modbus 子服务

底层命令：

  • firewall-cmd --add-forward-port=port=80:proto=tcp:toport=8080
  • firewall-cmd --add-forward-port=port=5020:proto=tcp:toport=5020:toaddr=192.168.0.50
⚠ 跨机器转发（填了目标 IP）需打开内核 IP forward：
sysctl -w net.ipv4.ip_forward=1 并写入 /etc/sysctl.conf。本机内转不需要。

3IP 规则（IP Rules）

基于来源 IP 整体放行或拉黑某台机器 / 某网段，不区分端口，比端口规则维度更高。

字段含义
族IPv4 / IPv6（程序按地址里有没有 : 自动判断）
IP / 网段单 IP 1.2.3.4 或 CIDR 1.2.3.0/24
策略允许 = 白名单；拒绝 = 黑名单

典型场景：

  • 黑名单：屏蔽爆破 SSH 的 IP
  • 白名单：只允许办公网段访问
  • 临时封网段，比一条条端口拒绝省事

底层命令：

  • --add-rich-rule='rule family="ipv4" source address="203.0.113.55" drop'
  • --add-rich-rule='rule family="ipv4" source address="192.168.0.0/24" accept'
⚠ firewalld 没有"匹配到 accept 就拒绝其他全部"的隐式 default-deny，单独建白名单不会把其他人挡掉。要严格白名单需把 zone 的 target 改为 DROP：firewall-cmd --set-target=DROP --permanent，本面板暂未暴露此项。

4三者关系速记

  • IP 规则 → 整台机器维度，不管端口
  • 端口规则 → 端口维度，可选限定来源 IP
  • 端口转发 → 流量改道，不是允许/拒绝，是把 A 端口的包送到 B 端口

实战建议：日常以端口规则为主，IP 规则做封禁/白名单，端口转发仅在确实需要端口映射时再用。所有改动都是 --permanent 写盘，重启不丢；删除是立刻从内核生效，操作 SSH（22 / 3010）端口时务必小心，别把自己关在外面。
