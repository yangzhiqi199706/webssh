# 运维设置完善设计

## 目标

将“规划中”的三项运维能力实现为服务端可执行、重启后仍生效的功能：WebSSH 日志自动轮转和保留、固定页面访问密码、仅 SSH 会话的闲置自动断开。

## 范围与约束

- 采用 Node 内置方案，不依赖目标机安装 `logrotate`。
- 保持用户名为 `admin`。
- 现有日期密码（服务器本地日期 `YYYYMMDD`）只作为首次配置固定密码前的兼容登录方式；固定密码配置成功后立即失效。
- 访问密码仅保护浏览器页面与新增运维配置接口，不改变既有自动化 API、协议助手代理和 WebSocket 的既有兼容性。
- 闲置策略只主动关闭 SSH 会话，不登出浏览器页面，也不影响串口或 TCP 调试连接。
- 日志轮转仅处理 `/opt/webssh/logs` 中由服务产生的 `*.log` 活动日志；不删除 HA 备份、上传文件或其它非日志产物。

## 配置与持久化

新增服务端运维配置文件（默认 `/opt/webssh/config/ops-settings.json`，可由环境变量覆盖），权限为 `0600`：

```json
{
  "logRotation": {
    "enabled": true,
    "retentionDays": 30,
    "lastRotationDate": "2026-07-30",
    "lastResult": null
  },
  "idleDisconnect": {
    "enabled": false,
    "timeoutMinutes": 30
  }
}
```

新增访问控制配置文件（默认 `/opt/webssh/config/access-control.json`，权限为 `0600`）：

```json
{
  "username": "admin",
  "password": {
    "algorithm": "scrypt",
    "salt": "hex 编码随机盐",
    "hash": "hex 编码摘要"
  }
}
```

密码永不以明文写盘、返回给浏览器或写进日志。更新密码时，后端校验当前密码；首次设置时当前密码按当天日期校验。

## 日志轮转

服务启动时以及每小时检查一次服务器本地日期。启用且当天尚未轮转时，对每个非空的 `*.log` 活动文件执行复制、gzip 压缩、成功后截断活动文件；归档文件命名为 `<原文件名>.<YYYYMMDD>.gz`。同一天手动再次轮转时追加 `-HHmmss` 后缀，避免覆盖已有归档。随后删除修改时间早于保留天数的同类归档文件。

使用 copy-truncate 适配 systemd `StandardOutput=append:` 与 `StandardError=append:` 的持续打开文件句柄。轮转状态及最近一次成功或失败信息写回运维配置；运维页允许立即执行一次轮转，并显示结果。

## 固定页面访问密码

登录接口读取访问控制配置。未配置固定密码时，沿用当前 `admin` + 服务器当天日期；配置后只接受 `admin` + 固定密码。密码摘要使用 Node `crypto.scryptSync`、随机 16 字节盐及时序安全比较。

运维页显示“页面访问密码”卡片：当前密码、新密码、确认新密码和保存按钮。设置成功后保留当前登录令牌；下次登录使用新密码。配置读取接口只返回“是否已设置”，不返回盐、摘要或密码。

## SSH 闲置自动断开

SSH WebSocket 在 SSH 已连接后创建可重置的服务端计时器。任何终端输入、远端终端输出或 SFTP 请求都会刷新活动时间。到达阈值时，服务端先发送 `idle_timeout` 错误消息，再关闭 SSH、Shell 和 WebSocket。

运维页提供开关与 1–1440 分钟阈值；初始状态为关闭，默认输入值为 30 分钟。连接时长上限仍独立存在，两种计时器任一到期都关闭该 SSH 会话。

## API 与界面

新增受登录校验保护的路由：

- `GET /api/ops-settings`：读取脱敏后的运维设置和轮转状态。
- `PUT /api/ops-settings`：校验并保存日志保留天数、轮转开关及 SSH 闲置策略。
- `POST /api/ops-settings/rotate-logs`：手动执行日志轮转，返回最近结果。
- `GET /api/access-control`：返回用户名及固定密码是否已设置。
- `PUT /api/access-control/password`：校验当前密码并写入新的 scrypt 摘要。

在“设置 → 运维”原 Docker 重启卡片之后，替换“规划中”提示为三个卡片。页面打开、保存配置及手动轮转后均刷新状态。所有错误通过现有提示方式呈现。

## 测试

新增可单测的 Node 模块：

- 访问控制：验证旧日期登录、scrypt 摘要不含明文、正确和错误密码的校验。
- 日志轮转：在临时目录验证 `.log` 压缩归档、活动日志截断、保留期清理，以及非日志文件不受影响。
- SSH 闲置计时器：使用可注入计时器验证活动刷新延后断开、取消后不触发。
- 设置页面：断言新增设置控件和 API 调用存在，防止未来回归为“规划中”占位。

所有既有测试继续纳入 `npm test`。
