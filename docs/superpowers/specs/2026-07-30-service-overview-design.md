# 服务总览设计

## 目标

在 webssh 主壳中新增“服务总览”页面，集中展示本机、双机热备对端与 `dcim` 容器的只读运行状态，并提供 7 天资源趋势和手动刷新。

## 数据采集

Node 服务启动后每 60 秒执行一次采样，并在页面请求手动刷新时立即执行一次。采集器使用本机系统接口和现有 HA 配置中的对端 SSH 连接：

- 两台主机：CPU 使用率、内存使用率、根分区磁盘使用率、1 分钟负载、运行时长。
- 两台主机：`webssh`、`webssh-protocol`、`docker` 的 systemd 状态。
- 两台主机：`dcim` 容器是否运行，以及容器内 `dcim` 采集服务状态。
- 对端连接失败时，保留本机结果，并将对端该次采样标记为“未知”与失败原因。

对端 SSH 密码仅在服务器端从既有 HA 配置读取，响应体不返回凭据。

## 存储与趋势

采样结果以本地 JSON 运行时数据保存，按时间顺序读取。每次写入使用原子替换，启动时和写入后清理 7 天以前的数据。趋势图展示 CPU、内存和根分区磁盘使用率，按主机分色；资源没有历史数据时显示空状态，不伪造数据。

## 页面与交互

左侧菜单增加“服务总览”。页面采用已确认的“运维指挥台”布局：

- 顶部显示本机/对端连接状态、最后采样时间和“手动刷新”。
- 资源卡片显示两台主机的即时指标与阈值颜色。
- 服务矩阵显示两台主机的 4 类关键服务与详情。
- 异常区列出不可达、服务非 active、容器未运行和资源超阈值的当前问题。
- 趋势区显示最近 7 天的 CPU、内存和磁盘曲线。

页面仅查询和刷新采样，不提供重启、切换、修改配置或任何写入目标主机的控制按钮。

## 阈值与错误处理

CPU、内存和磁盘使用率达到 80% 显示警告，达到 90% 显示严重。采集命令、对端 SSH 或历史文件失败时，后端返回明确的局部错误；其他主机与指标继续可用。手动刷新有并发保护，已有采样进行时复用同一个结果，避免重复 SSH 连接。

## 验证

测试覆盖指标解析、7 天历史裁剪、对端失败的降级结果、凭据脱敏、手动刷新并发保护以及前端菜单/API/只读边界。完整 `npm test` 通过后，使用主壳增量部署脚本部署并验证 `/health` 与服务总览 API。
