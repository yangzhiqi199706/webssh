# 第45章 - B接口SoapUI联调与SU端口访问修复

日期：2026-10-13
状态：功能记录

## 功能目标

核查注册及温度采集，补充指定上级IP访问SU端口的防火墙规则

## 开发范围

- `SoapUI测试文件`
- `指定上级IP访问SU端口`

## 关联文件

- `output/soapui-b-interface/GET_AIDATA-request.xml`
- `output/soapui-b-interface/SCService.wsdl`
- `output/soapui-b-interface/SUService.wsdl`

## 验证记录

- SoapUI 模拟 SC 的原始应答从默认 `invokeReturn=?` 改为有效 `LOGIN_ACK` 后，实际请求获得 HTTP 200，SOAP 字符串参数及业务 ACK 校验通过；界面显示 SC 已注册。
- 当前设备 3 的分组已留空，serverCode 为 1。通过现有 B 接口采集模块查询温度，返回数值 25.5；旧分组 1 的查询返回空列表。
- 192.168.50.61 的 SU 在 8079 监听，但 firewalld 的 public 区域未允许入站访问。修复前本机 SOAP 查询连接超时。
- 已添加仅允许来源 192.168.50.2/32 访问 TCP 8079 的 rich rule。运行时和永久规则查询均返回 yes，未执行全量防火墙重载。
- 修复后从本机向 SU 地址发送 `GET_AIDATA`，HTTP 200；实际业务应答为 `GET_AIDATA_ACK`、Code 202，Signal Value 为 25.5。原始响应保存在 `output/soapui-b-interface/GET_AIDATA-response.xml`。

## 实现摘要

- 本次仅生成本地 SoapUI 联调文件并修改指定服务器的端口访问规则，无应用源码、运行时依赖或服务重启。
- 本地 WSDL 按当前部署的 SOAP 1.1、invoke/xmlData/invokeReturn 配置生成，通过 XML 解析、内嵌 XSD 编译和绑定字段检查；不是联通官方 WSDL。
- 保留服务器业务配置及设备编码，由用户此前在界面完成分组调整。
- 目标服务器为 x86_64；没有 ARM 部署操作。应用共用源码没有改动，本次未重新打包任何架构安装包。

## 后续注意事项

- 当前静态 `LOGIN_ACK` 只能模拟注册应答。告警上报需按请求类型返回对应业务 ACK；保持注册还需按协议定期查询 SU。此项联调验证不代表全部 B 接口指令及告警链路已验证。
- 更换 SoapUI/SC 电脑 IP 时，需同步调整 SU 白名单及服务器来源 IP 防火墙规则。
- 后续扩展本功能时，新增下一章记录具体变更，不回写本章的已交付结论。
