## 实现摘要

- 共用源码新增 `kingbase` 数据库类型，使用已有 pg 纯 JS 驱动，无新增 npm 依赖。
- 金仓独立 SSH/容器字段留空时使用公共配置，设置独立主机时不覆盖原三库。
- 连接凭据只写本地已被 Git 忽略的配置，接口脱敏；示例配置不包含真实凭据。
- 原生备份还原在目标容器执行 sys_dump/sys_restore，使用唯一受限临时目录、完整 shell 引用以及失败清理。
- 数据库健康度以实际 SELECT 查询结果为准；systemd 状态保留作管理诊断。
- 库表浏览在所选数据库中查询，Schema 随查看操作传递，支持同名表及含短横线的表名。

## 后续注意事项

- 当前交付为本地源码与连接配置，未部署 WebSSH、未重打 x86/ARM 安装包。两种架构打包流程都包含共用 lib/ 和 db/；x86 Linux Node 12 未在本次实机验证，不能将此记录视为双架构安装包已更新。
- 本次未停止/重启业务数据库，也未对业务库执行还原。还原通过命令构造测试及归档可读性验证，完整写入还原仍需在隔离空库验证。
- 金仓还原只接收 sys_dump 自定义格式 .dump，目标库必须已创建；使用单事务和遇错退出，不自动删除现有对象，推荐空库。
- 应用代码包的「数据源切换」仍为原有三种业务版本，未把金仓数据库管理误当作 DCIM 应用迁移支持。
- 查询最多展示 5000 行，超大结果仍会由 pg 驱动先读取到内存；建议用户 SQL 自带 LIMIT。
- 后续扩展本功能时，新增下一章记录具体变更，不回写本章的已交付结论。
