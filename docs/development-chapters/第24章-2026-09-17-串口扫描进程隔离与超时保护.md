# 第24章 - 串口扫描进程隔离与超时保护

日期：2026-09-17
状态：功能记录

## 功能目标

将串口扫描的驱动访问移出主线程，避免异常设备拖住整个Web服务

## 开发范围

- 测试环境为 Windows / Node 24；既有测试中 `sh -n` 因本机无 sh 跳过。生产 Node 12 和实际 Linux 串口硬件尚未验证。

## 实现摘要

- 普通端口刷新和主动扫描均由独立 Node 子进程读取设备信息，主进程不执行串口驱动同步调用。
- 单次扫描总超时 8 秒，忙时返回 409，超时返回 504。每个设备探测前向主进程申请现有串口锁，避免与调试和转发任务抢占。
- 工作进程真正退出后才释放扫描槽位及残留设备锁。前端请求 12 秒超时，失败提示后恢复扫描与刷新按钮。
- 保留成功响应的 ports/probed 字段及原有端口属性，不新增依赖；增量部署脚本已包含整个 serial 目录。

## 后续注意事项

- 后续扩展本功能时，新增下一章记录具体变更，不回写本章的已交付结论。
- 当前无法连接生产环境，本次未部署、未重启服务器；不能据此认定生产事故最终根因已经确认。
- 若驱动陷入不可中断内核等待，SIGKILL 可能暂时不能使工作进程退出；此时扫描保持忙状态以避免任务堆积，Web 主进程仍可响应。需要排查现场驱动或设备。
- 扫描占用锁仅覆盖本服务管理的设备任务，无法阻止外部程序访问同一串口。
