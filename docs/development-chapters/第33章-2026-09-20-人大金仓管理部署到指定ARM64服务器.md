# 第33章 - 人大金仓管理部署到指定ARM64服务器

日期：2026-09-20
状态：功能记录

## 功能目标

定向部署人大金仓管理功能，保留现有ARM64运行时及原数据库配置

## 开发范围

- `三文件定向更新`
- `配置合并`
- `应用备份与回滚`
- `服务与数据库验证`

## 关联文件

- `server.js`
- `db/index.html`
- `lib/kingbase-manager.js`

## 验证记录

- `部署前两个服务active`
- `npm run test:kingbase通过`
- `ARM64运行时Node16已确认`
- 部署后 webssh、webssh-protocol 均 active；外部 /health 返回 200，/protocol/ 返回 200。
- /db/index.html 返回 200 且包含人大金仓卡片。
- 实际 /api/db-manager/status 返回金仓 online、4 库、134 表；SQL 查询、表列表及两类密码脱敏验证通过。
- 目标 ARM64 Node 16.20.2 运行新增适配器成功，返回金仓 V8 版本及 134 张业务表。

## 实现摘要

- 在目标服务器原 server.js 中仅替换 setupDbManager 区块，保留其他服务器现有功能；同步 db/index.html 和 lib/kingbase-manager.js。
- 三个上传文件均经 SHA256 校验，更新前在目标 Node 运行语法检查。
- 原应用完整备份为 `/opt/webssh/app.bak-kingbase-20260920063701`。
- 在远端数据库管理配置中仅合并 kingbase 项，保留原三库及公共 SSH 配置，文件权限 0600。临时凭据文件已清理。
- 重启 webssh 并验证联动协议助手；未重启 Docker 或业务数据库。

## 后续注意事项

- 本章记录用户指定 ARM64 目标的增量部署；x86 共用源码已在前章更新，本次未部署其他服务器，也未重新制作任何架构离线包。
- 恢复原功能可从上述备份恢复 server.js、db/index.html 和 config/db-manager.json 后重启 webssh。
- 后续扩展本功能时，新增下一章记录具体变更，不回写本章的已交付结论。
