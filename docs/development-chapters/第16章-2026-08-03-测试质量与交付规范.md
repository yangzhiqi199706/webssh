# 第16章 - 测试、质量与交付规范

日期：2026-08-03
状态：现有功能基线整理

## 功能目标

让新增功能、修复与部署具有可重复的验证记录，并把设计、实施计划和功能章节沉淀为可追溯资产。

## 开发范围

- Node 级回归测试和模块专项测试。
- 规格与实施计划文档。
- 功能章节档案、自动创建命令和章节目录。
- 部署后健康检查与人工端到端验证。

## 关联文件

- `package.json`
- `tests/`
- `docs/superpowers/specs/`
- `docs/superpowers/plans/`
- `docs/development-chapters/`
- `scripts/create-feature-chapter.js`

## 实现摘要

`npm test` 串联现有功能回归；章节工具使用 Node 内置模块自动计算下一章编号、写入统一模板并重建目录。`AGENTS.md` 规定功能性交付在提交或部署前必须创建章节并填写实际验证结果。

## 验证记录

- `node tests/feature-chapter-tools.test.js`：验证章节编号递增、模板创建和目录刷新。
- `npm test`：执行项目全量 Node 回归。
- `git diff --check`：检查文档与代码的空白错误。

## 后续注意事项

- 章节是交付记录，不替代规格、计划、测试代码或运维手册。
- 每个功能性变更应以新的章节追加历史，不能用修改旧章的方式掩盖版本差异。
